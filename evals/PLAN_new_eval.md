# 新しい評価の仕組み: 計画と引継ぎ

- 作成日: 2026-11-12（同日に、promptfoo の版を作って基準の値を測った）
- 状態: ブランチ `feat/evals-promptfoo`（2026-11-12 に main（`aed8b59`）から切った）に commit した
- 目的: 新方式（Decisions API → 条文の選択）を含む本番の判定のコードを、発注書 PJT04 の評価用データセット（6 言語・258 件）で、何度でも同じ条件で評価できるようにする。受講生が Bedrock 用の方式を足しても、同じ評価を流せるようにする
- 使い方と「何を計測するか」（指標 10 個の定義）は [README.md](README.md)

## 2. 基準の値（新方式・OpenAI 版。2026-11-12）

- 対象: 本番の判定のコード（`decisions`。今デプロイした新方式）。コードは main（`05b50a4`）の作業ツリー（判定に関わる差分なし）
- 実行: `npx promptfoo eval --repeat 3 --no-cache`（258 件 × 3 回。同時に 4 件）。開発用の API キー
- 集計: `summarize.py output/results.json`

| 言語 | 件数 | 取りこぼし | 誤検知 | 再現率 | 適合率 | F1 | 通知 | 判定の失敗 | 条文の一致 |

| **全体** | **258** | **3** | **4** | **0.978** | **0.971** | **0.974** | 136 | 0 | 124/132 |

- **安定性: 3 回とも 258/258 件で判定が同じ**。再現率・適合率も 3 回とも同じ（条文の一致は回によって少し動く。同日の暫定の実行では 122/132）
- 取りこぼし: W07-ja（宗教の勧誘。P(warn) 0.18）、W16-fr（録画の無断公開。0.30）、W16-sw（同。0.16）。W07-ja と W16-sw は、Decisions API の条文の候補の 1 位は正解（11-v 0.97、11-vi 0.71）なのに、警告の確率が低い
- 誤検知: S09（外部グループを禁じるルールの注意）の en・zh・ar・fr。S09-en は P(warn) がちょうど 0.500（しきい値 0.5 以上で違反）
- 条文の誤り: W06（正解 11-v → 11-xiii。Decisions API も 11-xiii を 1 位に）が 5 言語、W09（正解 11-x → 11-xiii）が 3 言語。**W09 は Decisions API の 1 位が正解の 11-x で、2 段目の条文の選択が 11-xiii に変えている**
- 言語の間の一致: 42 シナリオ中 39 件（0.929）。分かれたのは S09・W07・W16
- 判定の方法: 258 件すべて Decisions。Decisions API の応答はすべて 200（同日の暫定の実行では 1 回 503 があり、予備経路で判定した。再試行を入れた今の版では、503 でも予備経路に切り替える前に再試行する）
- 判定時間: 中央値 1.87 秒、95 パーセンタイル 3.33 秒、最大 9.63 秒
- 費用: このデータセットで 1 投稿 0.000530 ドル（警告した投稿 0.000600・警告しない投稿 0.000452）。本番の違反の割合 1% なら 1 投稿 0.000453 ドル・月 3 万投稿で約 13.6 ドル、5% なら約 13.8 ドル
- 3 回分の合計: 約 388 万トークン、所要 5 分

これを発注書の「運営が提供する OpenAI 版（新方式）の評価結果」として配布できる（集計の CSV は `output/summary.csv`）。

### 注意

- 外部の API を呼ぶ実行は費用がかかる（新方式で 258 件 × 1 回あたり約 0.14 ドル）
- 結果のファイル（`output/`）には投稿の本文が入る。commit しない・`--share` しない
- 件数が少ないので、改善の効果は件数と率を並べ、`--repeat` の結果で比べる
- 評価では Decisions API の一時的なエラーを再試行するが、本番のコードは再試行しない（ISS-33）。評価の値は「API が混雑していないとき」のもの
